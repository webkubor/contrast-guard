# 页面视觉评审（UI Review）

## 为什么需要这个 skill

「丑」是感受层，agent 的输入是判据层，中间缺翻译器。用户说「这页丑」，agent 只能在
CSS 里随机漂移——这是所有「AI 指导不动 UI」的直接原因。

更麻烦的是：**丑的每一处单看往往都"对"**。每个色值都是合法 token，每个圆角都在白名单里，
但一屏 9 种字号、灰阶只拉开 2 层、间距 11 种——每一条都过门禁，合起来就是丑。

所以 `frontend-e2e` 那套二值门禁（有没有、是不是 token）**结构上抓不到丑**。
本 skill 补的是**程度**：不问对错，问多少。

| | 判什么 | 例 |
|---|---|---|
| `frontend-e2e` | 对/错 | 字段缺没缺、交互通不通、色值是不是 token |
| **`ui-review`（本 skill）** | 程度 | 字号几种、灰阶几层、多少元素真有动效 |

## 何时触发

- 用户说「丑 / 难看 / 没设计感 / 太平 / 像模板 / 有 AI 味」——**不要直接去改 CSS，先跑本流程**
- 重设计 / 视觉打磨开工前，先量现状（否则改完无法证明变好）
- 定期视觉巡检、多端风格一致性核对

## 三步流程

### 1. 计量（拿数字，不靠肉眼）

```bash
contrast-guard measure <url>                      # 判据 + 参考量
contrast-guard measure <url> --vs <baseline>      # 与参照站基线逐项对比
contrast-guard measure <url> --json               # 出 JSON，需要自己算的时候用
```

渲染后计量：打开页面遍历所有可见元素的 `computedStyle`，统计实际生效值。
输入只有 URL，**零项目知识**——React/Vue/Astro/纯 HTML 一视同仁，
所以能用同一把尺子量自己的页面和参照站。

计量 CLI 的真实参数以当前 `contrast-guard measure --help` 为准。基线选项目改前版本、设计契约或任务相关参照，并记录视口、状态和版本；没有合适基线时可收集现状，不伪造及格线。

### 2. 看图与交互

使用当前环境浏览器截图并实际打开检查；记录视觉焦点、留白、对齐、比例与主要路径。视觉模型可以辅助提出假设，结论仍需回查截图、DOM、computed style 和实际交互。无需指定驱动、平台或本地模型。

### 3. 定位（每条都要能直接改）

产出格式固定为「成因 → 证据 → 位置 → 改成什么」：

```
⚠️ 卡片边界难辨｜在当前背景上无法快速区分可操作区域
   位置：卡片区 .stat-card 与页面背景同为 #fff
   改为：核对项目表面 token，试验层级差异并比较任务识别效果
```

**禁止**输出「建议优化视觉层次」「可以更精致一些」这类无法执行的话。
一条评审如果读完不知道改哪个文件的哪一行，这条就是废的。

## 判读指南：计量不是审美分数

字号、字体族、灰阶与动效覆盖率都是定位线索，没有跨产品通用及格线。阈值须来自项目契约、适用标准或同条件参考，注明用途、样本和失败影响。静态界面不因动效少判失败，多字体也可能是明确角色分工。先打开截图并追踪 token 与组件，再判断是否需要改动。

完整判定与覆盖矩阵以 [评审标准](https://github.com/webkubor/frontend-contrast-guard/blob/main/../) 为准。历史参照站的数据不作为新项目默认门禁。

## 成因清单（对着截图逐条查）

以下是排查假设，不是凭命中次数判丑的规则：

1. **层级压不住** —— 元素同权重，眼睛不知道看哪（查灰阶层数、字重跨度）
2. **层级未表达** —— 检查当前配色是否支持语义区分；黑白风格本身不是缺陷
3. **留白不足** —— 密度过高，元素互相挤压（最高频）
4. **对齐轴太多** —— 左边界不齐，视觉散
5. **字号台阶太密** —— 16/17/18 这种，人眼分不出只感到乱（查集中度）
6. **圆角/阴影不统一** —— 同屏多套规格
7. **颜色争抢任务焦点** —— 结合品牌和任务检查强调色分工
8. **边框滥用** —— 什么都描一圈线，该用背景色分层的地方用了边框
9. **比例失调** —— 图标、文字、按钮的大小关系随意

动效，丑的成因集中在六条：

1. **时长不匹配任务** —— 根据操作频率、移动距离、反馈延迟和项目动效契约判断；不存在全局 400ms 门槛
2. **曲线不匹配行为** —— 检查起止、可中断性和速度连续性；匀速进度可用 linear，手势可用弹簧，不按曲线名称判丑
3. **只有进场没有退场** —— 元素消失时啪一下没了
4. **该连续的做成了离散** —— 拖拽/滑动等松手才动，必须 1:1 跟手
5. **动了不该动的** —— 装饰动画抢注意力；动效应解释状态变化，不是表演
6. **没做 `prefers-reduced-motion`**

## 风格画像

给基线补充计量抓不到的角色、布局母题、材质、动效意图和辨识点。每项注明具体元素、位置或测量条件，避免「高级」「廉价」等无证据标签。记录项目认可的取舍，不复制参照站的绝对数字。

## 创意任务的补充检查

检查核心功能是否支持适用的触控与键盘路径，焦点是否可见，激活反馈是否可理解，减弱动效时是否保留内容和操作。位移、缩放、发光双环不是通用要求。

## 评审约束

- 截图、计量和行为证据相互核对；工具不可用时标明缺口，不编造数字。
- 所有整改写明任务影响、证据、位置与可验证假设。
- 没有项目契约或同条件参照时，不断言某个计量数字偏高或偏低。
