# 前端工程视觉评审与交互自适应规范标准（SSOT）

> **唯一真源声明**：本规范是全体前端工程、UI 组件、设计评审与交互自适应的唯一真源（SSOT）。
> CS 内部系统不再单独维护任何 UI 与样式评审细节，一律以此为准。
>
> 核心原则：**丑是感受层，不是判据层；二值门禁抓不对丑，必须靠视觉计量与视口硬断言。禁止用户说「丑」就直接盲改 CSS。**

## 一、视觉计量标准（量出来，不是看出来）

`contrast-guard measure <url>` 通过真实浏览器遍历所有可见元素的 `computedStyle`，统计实际生效值。
**任何框架都能量，阈值全部由高水准参照站（如 Linear 等）实测校准，不是拍脑袋定的。**

| 指标 | 判据 | 备注 |
|---|---|---|
| **动效覆盖率**（带 transition 的元素占比） | `<1%` 判定动效缺失，`<3%` 偏低 | 标杆站 ~9%，区分度最大 |
| **字号集中度**（前 4 种覆盖率） | `<80%` 判定碎片化 | **看分布集中度，不看种类数**（Linear 用 14 种字号，但前 4 种覆盖率 >85%） |
| **字体族数** | `>2` 判定混用 | 超过 2 种视为字体体系失控 |
| **背景灰阶层数** | `>40` 判定绕过 token；`<4` 判定层级压不住 | 标杆站 ~20 层 |
| **文字灰阶层数** | `<3` 判定主次未拉开 | 必须区分主文本、次要描述与占位弱灰 |
| **动效时长种类** | `>8` 判定未收敛到 token 档位 | 时长必须收敛至统一档位（如 150ms/250ms/350ms） |
| **圆角 / 阴影 / 间距种类数** | **仅参考，不设死判据** | 复杂现代页面天然层级丰富，无单一判别力 |

## 二、多视口响应式自适应度量标准（4 阶矩阵 · CRITICAL）

> **严禁只测死板桌面单尺寸（如 1440px）就声称完成！**  
> 事故证明：大屏下看着能塞下的卡片，在用户半屏、分屏或网格缩窄到 340px 时，右侧 `flex-shrink: 0` 徽标立刻把主标题反向压榨到 6 像素，字被切碎像乱码，用户名变成单字母。**不覆盖多视口梯级断点，所谓的 UI 验收就是摆设。**

每次 UI 验收必须通过真实浏览器遍历以下 4 阶响应式断点巡检，硬断言全部通过才算合规：

| 断点梯级 | 视口尺寸 (W×H) | 业务场景 | 必测硬断言 |
|---|---|---|---|
| **Mobile 极限窄屏** | `390 × 844` | 手机端 / 超窄分屏 | 无横向滚动条（`scrollWidth <= innerWidth`）、卡片单列自然换行、弹窗全宽自适应 |
| **Tablet-Split 临界分屏** | `768 × 1024` | 平板 / 桌面半屏工作区 | 3列切2列临界测试：**核心文本容器渲染宽度 ≥ 80px**、严禁文字垂直挤压折叠 |
| **Laptop 常用视口** | `1280 × 800` | 笔记本典型开窗 | 3列网格规整度、图表自适应收缩、抽屉/弹窗不产生遮挡 |
| **Desktop 宽屏** | `1600 × 900` | 宽屏显示器平铺 | 4列平铺无拉伸畸变、背景遮罩完整 |

## 三、盒模型排版与组件三硬铁律（一票否决项）

1. **主标题特权律（Anti-Squeeze Law）**：
   - 用户名、仓库名、工单标题等**第一识别物**，必须享有独立行或设置 `flex: 1; min-width: 0;`；
   - 徽章、标签、平台图标属于辅助信息，**严禁用 `flex-shrink: 0` 反向压榨主文字**；
   - 任何卡片的主标题在任意视口下的渲染宽度必须 `>= 80px`，**一旦被压缩成单个字母或出现字符垂直切碎，当场判不及格并阻止发布**。
2. **全局浮层避让律（Anti-Occlusion Law）**：
   - 严禁使用死板固定的大黑卡片（>100px）悬浮覆盖在内容边缘；
   - 全局提示（如新版本通知）必须采用**轻量微胶囊（高度 ≤ 36px）**，并具备**无操作自动避让收缩**机制，严禁遮挡宿主页面的按钮与卡片。
3. **动态交互端到端真实闭环**：
   - 所有抽屉、弹窗、二级页面，在验收阶段**必须用自动化浏览器真实 `click()` 触发一次**；
   - 展开后必须检验无 `404`、无 `SyntaxError` / `JSON parse` 报错，且数据直方图/图表正常渲染；
   - 接口必须支持别名与错误友好容错，严禁把技术底层堆栈直接糊到页面上。

## 四、组件选型与弹窗铁律

- **坚决拒绝垃圾原生系统弹窗**：严禁在任何业务代码中使用 `window.alert()`、`window.confirm()`、`window.prompt()`（工程门禁静态扫描拦截）；
- **优先复用项目成熟 UI 组件库**：项目已安装组件库（如 Naive UI、Ant Design、Shadcn UI）时，弹窗必须走组件库标准模态框，抽屉走标准 Drawer，轻提示走 Message / Notification；
- **自研 CSS 必须自洽**：严禁临时拼凑粗糙样式，所有色值走 Design Token，卡片内边距与按钮尺寸统一。

## 五、十大前端禁止红线

1. 禁止用户说「丑」就直接盲改 CSS —— 先跑 `contrast-guard measure` 计量，再定位成因。
2. 禁止只在一个死板的固定大尺寸（1440px）下看一眼就声称 UI 验收通过。
3. 禁止用 `flex-shrink: 0` 压榨主文字容器导致单字母或垂直截断。
4. 禁止手搓死板悬浮卡片遮挡页面基础交互控件。
5. 禁止在业务前端源码中使用原生 `alert / confirm / prompt`。
6. 禁止未做动态交互点击（`click()`）测试就交付抽屉与弹窗。
7. 禁止在没有参照基线的情况下主观断言某个数字「偏高/偏低」。
8. 禁止输出无法执行的泛泛评审结论（如「建议优化视觉层次」这类空话）。
9. 禁止手搓已有成熟组件库中现成的标准组件（优先复用，见 `library-before-handrolling`）。
10. 禁止硬编码十六进制颜色与圆角值，所有视觉变量必须绑定 Design Tokens。
