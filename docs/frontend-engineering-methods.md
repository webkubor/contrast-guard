# 前端工程通用方法

生效入口：[Flow](frontend-flow.md)；判定真源：[评审标准](frontend-review-standard.md)。本页从旧 CS 前端约定提取通用方法，去掉固定风格、品牌、域名、供应商命令与无法跨项目成立的硬阈值。

## 组件与主题

- 按 token 语义使用前景、背景、状态和边界色，检查实际主题作用域。不是所有 token 名都保证跨主题可互换；读项目定义并测量计算值。
- 用户要求参照现有组件时先查组件与变体，再复用；确有缺口才扩展。不要用一次性颜色覆盖代替已有 variant。
- 抽组件依据语义一致性、重复修改成本和 UX 碎片化，先检查真实使用场景；不以统一的行数/次数决定是否抽离。
- 接口状态、焦点、禁用、加载、空与错误状态按实际可交互范围检查，不机械要求非交互元素具有全部状态。

## 路由与数据

- 跳转前确认环境、站点/租户/市场、目标是否存在及权限。域名从项目指定配置读取；原型 URL 不自动获得生产权威。
- 原型的功能、布局、字段、交互与视觉约束以其明确标注范围为准。样式还原需正确设计对照；没有视觉授权时遵循项目设计系统，不能用原型过渡动画条数判断还原程度。
- 判定真实接口字段先看实际请求/响应与运行时日志，类型和注释用于辅助理解；日志缺失才重现请求。对敏感数据脱敏，禁止打印凭据来排查 UI。

## 资源与表达

字体、图片、动效按项目目标和实际成本决定。自定义字体按授权、子集化、格式和加载预算评估，不强制系统字体。单色基底、单字体、大留白、暗色主面等是可选方向，不能规定为所有项目的高级感模板。

交互应及时反馈、保持状态连续、允许必要的中断与恢复；动效服务信息变化，尊重 reduced-motion。图表保留单位、刻度、数据来源及必要的非颜色编码。

## 验证与交付

修复共享样式先查同模式的其他使用点；全局 token/主题属性须验证影响面。实际支持矩阵从项目读取，不强制每个项目双主题或同一四档宽度。

按 [ui-restore](../skills/ui-restore/SKILL.md) 采集参考/前后证据，按 [frontend-e2e](../skills/frontend-e2e/SKILL.md) 验字段和交互；最终版本/环境/发布约定跟随所属项目。工具提供观察，不用可用性测试冒充审美验收。

## 参考来源

旧 CS `frontend_conventions` 与 `ui-design-references` 中的组件复用、路由核查、运行时证据及状态完整性方法已在这里收敛；项目事故和品牌映射继续由项目维护。历史标杆如 Stripe、Linear、Vercel 可以启发具体问题的方案，但不产生跨产品字体/配色/动效门槛。
